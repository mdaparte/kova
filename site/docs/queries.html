Find and aggregate

Filters, projections, and a pipeline of stages over the pages of a collection.

find and the aggregation pipeline share one matcher. A leading $match runs while the pages are scanned. The pipeline is the BSON array a MongoDB shell already sends. There is no second syntax. The names are MongoDB's. Each link below is that operator in the MongoDB manual. Kova runs the operators on this page.

Predicates

Equality is { job: "CLERK" }. These operators work on find and inside $match. Numbers compare across int and double. Dates compare by instant.

OperatorMeaning
$eq $neEqual, or not equal.
$gt $gte $lt $lteOrdered comparison.
$in $ninValue is in a list, or outside it.
$existsThe field is present, or absent.
$and $or $norCombine predicates.
$notNegate one operator document.
$regexMatch a string field.
$typeMatch the BSON type of a field.
$elemMatchOne array element satisfies every predicate in the subdocument.
 
db.emp.find({
  sal: { $gte: 1000, $lt: 2000 },
  job: { $in: ["CLERK", "SALESMAN"] }
})
Output
[
  { empno: 7499, ename: 'ALLEN', job: 'SALESMAN', sal: 1600 },
  { empno: 7521, ename: 'WARD', job: 'SALESMAN', sal: 1250 },
  { empno: 7654, ename: 'MARTIN', job: 'SALESMAN', sal: 1250 },
  { empno: 7844, ename: 'TURNER', job: 'SALESMAN', sal: 1500 },
  { empno: 7876, ename: 'ADAMS', job: 'CLERK', sal: 1100 },
  { empno: 7934, ename: 'MILLER', job: 'CLERK', sal: 1300 }
]
SELECT empno, ename, job, sal
FROM emp
WHERE sal >= 1000 AND sal < 2000
  AND job IN ('CLERK', 'SALESMAN')
Output
empno  ename    job       sal
7499   ALLEN    SALESMAN  1600
7521   WARD     SALESMAN  1250
7654   MARTIN   SALESMAN  1250
7844   TURNER   SALESMAN  1500
7876   ADAMS    CLERK     1100
7934   MILLER   CLERK     1300
MQL
db.emp.find({ ename: { $regex: "^S" } })
Output
[
  { empno: 7369, ename: 'SMITH', job: 'CLERK', sal: 800 },
  { empno: 7788, ename: 'SCOTT', job: 'ANALYST', sal: 3000 }
]

A find with no projection returns every stored field, including _id. The rows above keep the fields the predicate is about.

Shape the rows

Projection, sort, skip, and limit work on find and as pipeline stages. Include fields, or exclude them. Mixing include and exclude in one projection is limited the way MongoDB limits it: _id is the field you may turn off while including others. The stages are $project, $sort, $skip, and $limit.

MQL
db.emp.aggregate([
  { $match: { deptno: 20 } },
  { $project: { ename: 1, sal: 1, _id: 0 } },
  { $sort: { sal: -1 } },
  { $skip: 1 },
  { $limit: 3 }
])
Output
[
  { ename: 'FORD', sal: 3000 },
  { ename: 'JONES', sal: 2975 },
  { ename: 'ADAMS', sal: 1100 }
]

SCOTT and FORD both have sal 3000, so the skipped row is one of those two. The three rows above are the rest, highest salary first.

$addFields keeps the document and adds fields. $replaceRoot makes a subdocument the new root. $unwind emits one document per array element. $count emits one document with the number of rows that reached that stage.

Group

$group buckets documents by _id. Accumulators:

AccumulatorResult
$sum $avgTotal, or mean, of a numeric expression.
$min $maxSmallest or largest value.
$countHow many documents landed in the bucket. Write { $sum: 1 }.
$first $lastThe first or last value seen in the bucket.
$push $addToSetAn array of values. $addToSet keeps each value once.
 
db.emp.aggregate([
  { $group: {
      _id: "$job",
      headcount: { $sum: 1 },
      payroll: { $sum: "$sal" }
  }},
  { $sort: { payroll: -1 } }
])
Output
[
  { _id: 'MANAGER', headcount: 3, payroll: 8275 },
  { _id: 'ANALYST', headcount: 2, payroll: 6000 },
  { _id: 'SALESMAN', headcount: 4, payroll: 5600 },
  { _id: 'PRESIDENT', headcount: 1, payroll: 5000 },
  { _id: 'CLERK', headcount: 4, payroll: 4150 }
]
SELECT job, COUNT(*) AS headcount, SUM(sal) AS payroll
FROM emp
GROUP BY job
ORDER BY payroll DESC
Output
job        headcount  payroll
MANAGER    3          8275
ANALYST    2          6000
SALESMAN   4          5600
PRESIDENT  1          5000
CLERK      4          4150

The rows match. SQL is one statement. The pipeline is how you add a lookup or write the result out.

Look up another collection

$lookup reads a second collection through the buffer pool. Equality uses localField and foreignField. The two collections are not copied into one big list first.

MQL
db.emp.aggregate([
  { $match: { ename: "SMITH" } },
  { $lookup: {
      from: "dept",
      localField: "deptno",
      foreignField: "deptno",
      as: "department"
  }}
])
Output
[
  {
    ename: 'SMITH',
    deptno: 20,
    department: [ { deptno: 20, dname: 'RESEARCH', loc: 'DALLAS' } ]
  }
]

let plus a nested pipeline runs that pipeline for each local document. A $match inside it accepts $expr.

On a shard router, $group runs on each shard and the router merges $sum, $min, $max, $avg, and $count. An accumulator that cannot merge is refused, and the error names it. Equality $lookup sends the join keys to the shards that hold the other collection. A stage after the group or the lookup is refused by name. A $group sent to one shard is only that shard's group.

Write the result

$out inserts the pipeline result into a collection. That write goes through the log, like any other insert.

MQL
db.emp.aggregate([
  { $match: { sal: { $gt: 2000 } } },
  { $project: { ename: 1, sal: 1 } },
  { $out: "high_earners" }
])
Output
{ ok: 1 }

Inside a transaction, $out is refused. The transaction page explains what a transaction can see.

An empty pipeline

aggregate with an empty pipeline returns the collection. An unknown stage or operator fails the command and names what it rejected.
