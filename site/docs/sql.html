SQL

Send a SQL string to the same server that stores the documents. One FROM, the database you connected to.

SQL runs inside the server. DataFusion plans it. The collections are the tables. A command-line client, a driver, and the ODBC driver all end up at this command:

db.emp.find({ sal: { $gt: 2000 } }, { ename: 1, job: 1, sal: 1, _id: 0 })
Output
[
  { ename: 'JONES', job: 'MANAGER', sal: 2975 },
  { ename: 'BLAKE', job: 'MANAGER', sal: 2850 },
  { ename: 'CLARK', job: 'MANAGER', sal: 2450 },
  { ename: 'SCOTT', job: 'ANALYST', sal: 3000 },
  { ename: 'KING', job: 'PRESIDENT', sal: 5000 },
  { ename: 'FORD', job: 'ANALYST', sal: 3000 }
]
SELECT ename, job, sal FROM emp WHERE sal > 2000
Output
ename   job        sal
JONES   MANAGER   2975
BLAKE   MANAGER   2850
CLARK   MANAGER   2450
SCOTT   ANALYST   3000
KING    PRESIDENT 5000
FORD    ANALYST   3000

The database is $db. In the shell, that is the database you opened. There is one FROM. A join is outside this statement. Combine collections with $lookup in the pipeline, then read the result, or write it with $out and select from that collection.

What a statement can do

  • SELECT with a target list, including SELECT 1 AS n with no FROM.
  • WHERE with comparisons. One comparison, such as sal > 1000 or job = 'CLERK', uses the same index a find would use. DataFusion checks the predicate again.
  • COUNT(*) and GROUP BY.
  • SHOW INDEXES FROM emp, also SHOW INDEX and SHOW KEYS.

Names are case-sensitive, and they are the collection names. The sample uses lowercase emp so FROM emp hits those rows. FROM EMP is a different collection.

db.emp.aggregate([
  { $group: {
      _id: "$job",
      n: { $sum: 1 },
      payroll: { $sum: "$sal" }
  }}
])
Output
[
  { _id: 'MANAGER', n: 3, payroll: 8275 },
  { _id: 'ANALYST', n: 2, payroll: 6000 },
  { _id: 'SALESMAN', n: 4, payroll: 5600 },
  { _id: 'PRESIDENT', n: 1, payroll: 5000 },
  { _id: 'CLERK', n: 4, payroll: 4150 }
]
SELECT job, COUNT(*) AS n, SUM(sal) AS payroll FROM emp GROUP BY job
Output
job        n  payroll
MANAGER    3  8275
ANALYST    2  6000
SALESMAN   4  5600
PRESIDENT  1  5000
CLERK      4  4150

The cursor rows use the column names from the statement. Integers you stored as BSON ints come back as integers.

Text in the WHERE clause

WHERE TEXT '…' is handled before the SQL planner, because a bare TEXT token is not standard SQL. It is the same search as $text. The view or collection needs the text index. After the sample is loaded, that view is emp_search.

db.emp_search.find({ $text: { $search: "clerk" } })
db.emp_search.find({ $text: { $search: "clrek", $fuzzy: 0.3 } })
db.runCommand({
  sql: "SELECT facet, bucket, doc_count FROM emp_search WHERE TEXT 'clerk' FACETS job TERMS, sal RANGES (1500), (1500, 3000), (3000)"
})
Output
[
  { ename: 'SMITH', job: 'CLERK', sal: 800 },
  { ename: 'ADAMS', job: 'CLERK', sal: 1100 },
  { ename: 'JAMES', job: 'CLERK', sal: 950 },
  { ename: 'MILLER', job: 'CLERK', sal: 1300 }
]
SELECT ename, job, sal FROM emp_search WHERE TEXT 'clerk'
SELECT ename, job, sal FROM emp_search WHERE TEXT 'clrek' FUZZY 0.3
SELECT facet, bucket, doc_count
FROM emp_search
WHERE TEXT 'clerk'
FACETS job TERMS, sal RANGES (1500), (1500, 3000), (3000)
Output
ename   job        sal
SMITH   CLERK       800
ADAMS   CLERK      1100
JAMES   CLERK       950
MILLER  CLERK      1300

ename   job        sal
SMITH   CLERK       800
ADAMS   CLERK      1100
JAMES   CLERK       950
MILLER  CLERK      1300

facet  bucket      doc_count
job    CLERK       4
sal    ..1500      4
sal    1500..3000  0
sal    3000..      0

FUZZY takes a fraction from 0 to 1. FACETS replaces the selected columns with three: facet, bucket, doc_count. TERMS buckets by value. RANGES buckets a number. The open end (1500) is everything up to 1500, and a trailing (3000) is everything above 3000. The full rules are on Text search.

From a client that only speaks SQL

The ODBC driver sends the string you typed and returns the rows. Connection keys are on the ODBC page. The server must already be running. SQL does not start it.
