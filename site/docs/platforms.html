Operating systems

Linux, Windows, and Mac ship the same Kova server. The package, the service, the ODBC driver, and one detail of the bundled Iggy binary follow the operating system.

A merge into main publishes four builds. Linux is an x86_64 archive and the container image. Windows is an x64 installer. Mac is an Apple silicon disk image. There is no Intel Mac build, no Windows on ARM, and no Linux on ARM. Documents, port 27018, and the MongoDB wire do not change with the machine. Install steps are on Getting started.

What stays the same

kova, kovadump, kova-shell, and kova-client are the same programs on each system. kova-shell is the terminal client. kova-client is the window. Both talk to a server that is already running. A machine without a display uses kova-shell. A client uses 127.0.0.1 and port 27018 on each system. Kova does not start iggy-server. The setup can install a service that starts it. The bundled binary is Apache Iggy tag server-0.5.0, the server that matches the Iggy client 0.7 inside Kova. It listens on 127.0.0.1:8090. The feed record is the same JSON. The feed stays off until [feed] is enabled. The record is on Feed.

Linux

The archive is kova-x86_64-unknown-linux-gnu.tar.gz. install.sh puts kova, kovadump, kova-shell, kova-client, and iggy-server on PATH, and libkova.so beside them. That library is the ODBC driver. unixODBC loads it. A service from the setup window is a systemd unit. The window needs WebKitGTK 4.1. The container image ghcr.io/mdaparte/kova is the server from this Linux build. It does not include kova-shell or kova-client.

iggy-server on Linux is the tag as Apache publishes it. When it opens a messages file it calls posix_fadvise. That asks the kernel to expect sequential reads. The call does not change the bytes in the file, and it is not part of the protocol.

Windows

Run Kova-x64-setup.exe. It is not signed. Windows SmartScreen asks for confirmation. The installer puts kova.exe, kova-setup.exe, kovadump.exe, kova-shell.exe, kova-client.exe, kova.dll, and iggy-server.exe in C:\Program Files\Kova. The Start menu has a shortcut for kova-client.exe. Opening Kova from the installer still runs kova-setup --window. kova.dll is the 64-bit ODBC driver named Kova. A 32-bit program does not see it. The setup window can install the Windows services Kova and, when the bundled Iggy is chosen, KovaIggy. Starting KovaIggy needs Python 3.11 or newer on Path, because the helper reads kova.toml with tomllib.

iggy-server.exe is still tag server-0.5.0. That tag refuses to compile on Windows, and its segment readers call two Unix-only functions. The Windows build applies packaging/windows/iggy-server-0.5.0-windows.patch before compiling. The patch removes the line that stops the compile. It reads a segment with seek_read and keeps reading until the buffer is full. On Linux and Mac that fill is read_exact_at. Both calls return the same bytes from the same file offset. The patch does not call posix_fadvise. Mac already skips that call. A feed client that speaks Iggy 0.7 can use the Windows binary, the Mac binary, or the Linux binary.

Mac

Kova-aarch64.dmg is for Apple silicon. Open it and drag Kova to Applications. The disk image is not notarized. The first open is a right-click, then Open. There is no ODBC driver in the Mac build. The setup window can install a login item. kova-shell and kova-client are inside the app. Opening the app still runs the setup window. iggy-server is inside the app and is the tag as Apache publishes it. The tag already skips posix_fadvise on macOS, which is the same omission the Windows patch makes.
