Welcome

Kova stores documents, answers SQL, and searches text. One process, one port, the MongoDB wire.

You talk to Kova with a MongoDB driver. The listener speaks the MongoDB wire protocol on port 27018. Insert a document, find it, run a SQL string over the same rows, or search the text. The files on disk are the database. Restart the process and the documents are still there.

How a write lands

A client sends a command. Kova appends that change to a log on disk, then updates the page that holds the document. The reply means the log has the change. A checkpoint later folds those pages into the data directory and shortens the log. If the process stops in between, startup replays the log and the document comes back.

RAM holds a cache of pages, called the buffer pool. A find that misses the cache reads the page from disk. The collection does not have to fit in memory.

One process, until you ask for more

The default kova.toml is one writable process. It stores every document you insert. Security is off, so a client connects and sends commands. Turn security on when you want a user and a password. Add a replica set when you want copies of the same data. Add shards when one machine cannot hold the collection or the writes.

A feed of committed writes, published to Apache Iggy, is planned. It is off. The shape of the record is on the Feed page. Today a program reads with find, or tails local.oplog.rs on a replica set.
