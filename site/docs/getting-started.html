Getting started

Install Kova, start it on port 27018, insert a document, and read it back after a restart.

Each merge into main publishes a Linux x86_64 build and a container image. Both are the optimized server. The examples use mongosh, the MongoDB shell. A driver in another language sends the same commands to the same port. The server itself does not need a MongoDB installation.

Install

This downloads the current build and installs it under your home directory:

Shell
curl -fsSL -o install.sh https://github.com/mdaparte/kova/releases/latest/download/install.sh
sh install.sh
Output
Installed into /home/ada/.local
  /home/ada/.local/bin/kova
  /home/ada/.local/bin/kovadump
  /home/ada/.local/lib/libkova.so
  /home/ada/.local/share/kova/kova.toml
Start from a directory you want to keep. Pages and the log go to data/ there:
  mkdir -p "$HOME/kova-data" && cd "$HOME/kova-data"
  KOVA_CONFIG=/home/ada/.local/share/kova/kova.toml kova

kova and kovadump land in ~/.local/bin. libkova.so lands in ~/.local/lib. The config and the sample script land in ~/.local/share/kova. If ~/.local/bin is not on PATH, the script prints the line to add.

To put the files somewhere else, download the archive and run its installer with PREFIX set:

Shell
curl -fsSL -o kova.tar.gz https://github.com/mdaparte/kova/releases/latest/download/kova-x86_64-unknown-linux-gnu.tar.gz
tar -xzf kova.tar.gz
PREFIX=/opt/kova ./kova-x86_64-unknown-linux-gnu/install.sh
Output
Installed into /opt/kova
  /opt/kova/bin/kova
  /opt/kova/bin/kovadump
  /opt/kova/lib/libkova.so
  /opt/kova/share/kova/kova.toml

The archive has a .sha256 file next to it on the same release, for checking the download.

Docker

The same build is the image ghcr.io/mdaparte/kova. The tag latest is the newest merge. A tag with the commit id is that exact build. Pages and the log stay in the volume kova.

Shell
docker run --rm -p 27018:27018 -v kova:/var/lib/kova ghcr.io/mdaparte/kova:latest
Output
[Kova] 2026-10-27 08:50:01.000 INFO - Kova engine starting (port 27018, log level info, data_dir data, wal_fsync=true, warn_on_non_mongo_queries=true)
[Kova] 2026-10-27 08:50:01.012 INFO - Network server started on port 27018 (max_connections 128, idle_ms 0)

The listener inside the container is on port 27018, published on the same port of the machine. -e KOVA_PORT=27019 changes the port inside the container. Publish that port with -p 27019:27019. The rest of this page talks to 127.0.0.1:27018 either way.

The sample script is in the image at /usr/share/kova/seed-oracle.js.

Shell
docker run --rm --entrypoint cat ghcr.io/mdaparte/kova:latest /usr/share/kova/seed-oracle.js > seed-oracle.js

Start the server

Start from a directory you want to keep. Pages and the log are created in data/ there.

Shell
mkdir -p "$HOME/kova-data" && cd "$HOME/kova-data"
KOVA_CONFIG="$HOME/.local/share/kova/kova.toml" kova
Output
[Kova] 2026-10-27 08:50:01.000 INFO - Kova engine starting (port 27018, log level info, data_dir data, wal_fsync=true, warn_on_non_mongo_queries=true)
[Kova] 2026-10-27 08:50:01.012 INFO - Network server started on port 27018 (max_connections 128, idle_ms 0)

The listener binds 0.0.0.0:27018. Leave that process running. A second terminal is where you send commands.

Port 27018 is deliberate, so a local MongoDB on 27017 can stay up beside Kova. Override it for one run with KOVA_PORT=27019 in front of kova. The matching client then uses that port too. KOVA_LOG_LEVEL=debug raises the log for that run.

Write the first document

Open a shell against database shop:

Shell
mongosh "mongodb://127.0.0.1:27018/shop"

Insert one order and read it back.

MQL
db.orders.insertOne({ sku: "kettle", qty: 2 })
db.orders.find({ sku: "kettle" })
Output
{
  acknowledged: true,
  insertedId: ObjectId('674a1c0e8f0a4b6d9c12e001')
}
[
  {
    _id: ObjectId('674a1c0e8f0a4b6d9c12e001'),
    sku: 'kettle',
    qty: 2
  }
]

Kova fills _id with an ObjectId when you omit it. The reply from insertOne includes that id. find returns the document you stored.

The same read from a shell and from a SQL client:

db.orders.find({ qty: { $gt: 1 } }, { sku: 1, qty: 1, _id: 0 })
Output
[
  { sku: 'kettle', qty: 2 }
]
SELECT sku, qty FROM orders WHERE qty > 1
Output
sku     qty
kettle    2

One FROM. The database is the one in the connection, here shop. A shell can also send the statement with db.runCommand({ sql: "..." }).

Stop, start, read again

Stop the server with Ctrl-C in the terminal that runs it. Start it again with the same kova command, from the same directory.

Open the shell and run the find once more. The kettle is still there. The write was appended to the log under data/ before the insert reply, and startup replays anything a checkpoint had not folded into the pages yet.

Deleting data/ starts empty. Keep that directory if you want the documents.

Load the sample

The install includes a small company sample: employees, departments, salary grades, and a few bonuses. With the server already listening:

Shell
mongosh --quiet "mongodb://127.0.0.1:27018/db" --file "$HOME/.local/share/kova/seed-oracle.js"

That drops database db and loads it again. It also creates five indexes on emp and two views, well_paid and emp_search. Your shop database is untouched.

Shell
mongosh "mongodb://127.0.0.1:27018/db"
MQL
db.emp.find({ job: "CLERK" }, { ename: 1, sal: 1, _id: 0 })
Output
[
  { ename: 'SMITH', sal: 800 },
  { ename: 'ADAMS', sal: 1100 },
  { ename: 'JAMES', sal: 950 },
  { ename: 'MILLER', sal: 1300 }
]
db.emp.find({ sal: { $gt: 2000 } }, { ename: 1, job: 1, sal: 1, _id: 0 })
Output
[
  { ename: 'JONES', job: 'MANAGER', sal: 2975 },
  { ename: 'BLAKE', job: 'MANAGER', sal: 2850 },
  { ename: 'CLARK', job: 'MANAGER', sal: 2450 },
  { ename: 'SCOTT', job: 'ANALYST', sal: 3000 },
  { ename: 'KING', job: 'PRESIDENT', sal: 5000 },
  { ename: 'FORD', job: 'ANALYST', sal: 3000 }
]
SELECT ename, job, sal FROM emp WHERE sal > 2000
Output
ename   job        sal
JONES   MANAGER   2975
BLAKE   MANAGER   2850
CLARK   MANAGER   2450
SCOTT   ANALYST   3000
KING    PRESIDENT 5000
FORD    ANALYST   3000

well_paid is the employees with sal above 2000. emp_search is every employee, with a text index on disk. Both are covered on the Views and Text search pages.

Rust crate

The crates.io package name is kovadb. The library name stays kova. After version 0.1.0 is published, cargo install kovadb installs the kova and kovadump binaries. A program that embeds the server depends on the package and calls kova::serve().

That version is published from GitHub Actions when a merge into main changes the crate sources. It is not on crates.io yet.

Config
kovadb = "0.1"
Shell
cargo install kovadb
Output
Installed package `kovadb v0.1.0`
binary: kova
binary: kovadump
Rust
#[tokio::main]
async fn main() {
    kova::serve().await;
}

The dependency uses the package name kovadb. The code uses the library name kova. serve is the same process the kova binary starts.
