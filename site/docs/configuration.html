Configuration

kova.toml sets the port, the data directory, and the optional security, replica, and shard sections.

The server reads kova.toml from the working directory. Point KOVA_CONFIG at another file to load a different profile. Every key can also be set with an environment variable. The environment wins over the file, and the file wins over the built-in default.

Sections you leave commented stay off. A default file is one process, security off, no replicas, no shards.

Listener

KeyDefaultEnvironment
port27018KOVA_PORT
max_connections128KOVA_MAX_CONNECTIONS
max_connection_idle_ms0, idle close offKOVA_MAX_CONNECTION_IDLE_MS
log_levelinfoKOVA_LOG_LEVEL (debug, info, warn, error)
warn_on_non_mongo_queriestrueKOVA_WARN_NON_MONGO_QUERIES

Past max_connections the listener accepts the socket, replies with an error, and closes it. That socket is not counted in connectionsActive. KOVA_LOG_LEVEL=debug kova raises the log level for that run.

The warning flag logs a WARN when a query uses a Kova extension such as $text.$boost or $text.$decay, or an operator the engine does not implement. Set it to false to silence those lines. The query still runs when the extension is supported.

Search

[search]
analyzer = "default"
stopwords = []

default splits on punctuation and whitespace, then lowercases. en_stem adds English stemming. stopwords is an extra list removed at index time and at query time. The analyzer is fixed when the text index is built.

Storage

KeyDefaultWhat it changes
data_dirdataRoot for pages, the log, and replica state. Environment KOVA_DATA_DIR.
page_size16384Page envelope in bytes. The payload inside is zstd-compressed, so the file is often shorter. KOVA_PAGE_SIZE.
buffer_pool_pages4096Pages kept in RAM per partition. KOVA_BUFFER_POOL_PAGES.
wal_fsynctrueFlush every log append before the page changes. KOVA_WAL_FSYNC.
wal_segment_bytes16777216Roll the log to a new file around this size.
checkpoint_every128Snapshot after this many mutations. Shutdown also checkpoints. 0 disables the periodic snapshot.

Give each process its own data_dir when you run more than one. Sharing a directory between two processes corrupts the pages.

Sections that start off

[security], [replication], and [sharding] are commented in the shipped file. Uncomment a section only when you want that behavior. The pages for them have the keys and a worked layout:

  • Security
  • Replica sets
  • Sharding

[feed] is reserved for a later release. Leaving it out changes nothing. The intended keys are on Feed.
